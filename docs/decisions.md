# 구현 중 내린 판단 기록

계획(`docs/superpowers/plans/2026-10-30-laymaker-editor.md`)과 다르게 구현했거나, 계획에 없던 것을 정한 기록입니다. 각 항목 끝에 "틀렸을 때의 비용"을 적었습니다.

## 코어와 확장 시스템

1. **스펙에 없는 타입을 미리 선언.** `Editor`, `EditorUI` 등을 타입 스텁으로 먼저 두고, 옵션 타입은 `core/types.ts`에 모았습니다. 태스크마다 타입 검사를 통과시키기 위해서입니다. 비용: import 경로 이동 정도.
2. **style 출력은 브라우저가 정규화한 형식.** ProseMirror가 `cssText`로 style을 쓰기 때문에 출력이 `style="text-align: center;"`이고 색상은 `rgb()`로 나옵니다. 비용: 픽스처 문자열만 바뀜.
3. **아이콘이 있을 때만 UI 항목 생성.** `blockExtension`은 `icon`이 있을 때만 UI 항목을 만듭니다(제목처럼 자체 드롭다운이 있는 경우 대비). 비용: 없음.
4. **줄바꿈만 있는 문서는 빈 문서.** `<p><br></p>`, `<div><br></div>`는 빈 문서로 보고 `getHTML()`이 `''`를 돌려줍니다. 비용: 일부러 빈 줄만 쓴 문서는 `''`로 저장됨.
5. **destroy 때 textarea 동기화.** textarea 모드에서 destroy하면 최종 HTML을 textarea에 넣습니다(`onChange`는 호출하지 않음). 비용: 없음.
6. **error 리스너가 없으면 콘솔로.** 리스너가 없을 때만 `console.error`로 보냅니다. 비용: 없음.
7. **`EditorOptions`를 두 부분으로 분리.** 핵심 옵션 + `{ [확장 이름]: 옵션 }` 교차 타입으로 바꿨습니다. `Omit`이 인덱스 시그니처 때문에 이름 있는 키를 모두 지우는 문제 때문입니다. 비용: 타입 이름 변경.
8. **`setHTML`은 실행 취소 기록에 남기지 않음.** 리뷰에서 Minor로 분류됐지만 Important로 올려 수정했습니다. 불러온 내용이 Ctrl+Z 한 번에 사라지는 것을 막기 위해서입니다. 비용: `setHTML`로 바꾼 내용은 되돌릴 수 없음(55에서 실행 취소 기록도 비우도록 확장).

## 서식과 블록

9. **드롭다운 하위 항목의 키 규칙.** 하위 항목 ID는 `heading:2`, `align:center`이고, 문구 키는 `option.<항목>.<옵션>`입니다. `toolbar.heading` 문자열과 `toolbar.heading.paragraph` 객체가 충돌하기 때문입니다. 비용: 키 이름만 다름.
10. **굵게의 `<b>` 판정.** `<b>`는 `font-weight:normal`이 아닐 때만 굵게로 봅니다(구글 문서 래퍼 대응). 배경색 span 규칙은 `span` 태그로 한정해서 표 셀 배경이 형광펜으로 바뀌지 않게 했습니다. 비용: 파싱 차이.
11. **표의 Tab 우선순위는 150.** 계획은 300이었지만 150으로 낮췄습니다. 표 안의 목록에서 Tab이 들여쓰기를 먼저 하게 하기 위해서입니다. 비용: 없음.
12. **셀 배경색 옵션과 해제 명령 추가.** `table.cellColors` 옵션과 `clearCellBackground` 명령을 추가했습니다. 비용: 없음.
13. **`blockExtension`에 `tagRule` 추가.** 코드블록이 공백을 보존하고 언어를 읽게 하기 위해서입니다. 비용: 없음.
14. **링크 주소에 스킴 자동 보완.** `naver.com`은 `https://`, 이메일은 `mailto:`를 붙입니다(리뷰 반영). 비용: 상대 경로로 쓰려던 `a.com` 형태의 입력도 외부 링크가 됨.

## 붙여넣기

15. **스타일→태그 변환은 모든 출처에 적용.** 굵게·기울임·밑줄·취소선 스타일을 태그로 바꾸는 처리를 Word·구글 문서뿐 아니라 일반 웹 붙여넣기에도 적용합니다. 비용: 없음.
16. **기본 검정 글자색과 흰 배경 제거.** 다크 모드에서 글자가 안 보이는 것을 막기 위해서입니다. 비용: 의도한 검정색도 사라짐.
17. **한글(HWP) 판정 기준.** HStyle 클래스, 함초롬 글꼴, HwpEditor로 판정합니다. Chrome이 모든 클립보드에 `StartFragment`를 넣기 때문에 그것은 쓰지 않습니다. 비용: 특이한 HWP 출력은 정리를 덜 받음.
18. **에디터 내부 복사·붙여넣기는 정리 생략.** ProseMirror가 표시한 클립보드(`data-pm-slice`)는 정리하지 않습니다(이미지 너비 등 보존). 비용: 없음.
19. **HTML이 같이 있으면 이미지 파일은 업로드하지 않음.** Word가 HTML 옆에 그림 스냅샷을 같이 넣기 때문입니다. 비용: HTML과 스크린샷이 같이 오면 HTML 쪽을 씀.

## UI

20. **패널을 닫을 때 포커스 복귀 조건.** 포커스가 패널 안에 있었을 때만 에디터로 돌려줍니다. 비용: 없음.
21. **`disabled` 대신 `aria-disabled`.** 툴바 탐색 중 포커스를 잃지 않게 하기 위해서이고, 현재 상태인 항목은 비활성으로 보이지 않습니다. 비용: 없음.
22. **본문 클래스와 테마 범위 조정.** `le-prose`를 ProseMirror 요소로 옮기고, 토큰 범위를 단독 `.le-prose`로 한정했습니다. 스크린샷 검사에서 발견한 다크 모드 글자 안 보임 문제를 고친 것입니다. 비용: 없음.
23. **`syncSelection()` 추가.** 패널을 열기 전에 브라우저의 선택 영역을 강제로 반영합니다. Shift+Home 직후 Mod-k를 누르면 링크가 엉뚱한 곳에 걸리는 E2E 간헐 실패를 고친 것입니다. ProseMirror의 비공개 필드를 쓰므로, 비용: ProseMirror를 업그레이드할 때 경합 문제가 조용히 되살아날 수 있음.
24. **공용 입력 폼 `inputForm`.** 이미지·동영상·대체 텍스트 패널이 함께 씁니다. 비용: 없음.
25. **UI 항목에 `text`와 `labelParams` 추가.** "50%" 같은 글자 버튼을 만들기 위해서입니다. 비용: 없음.
26. **업로드 관리자는 처음 쓸 때 생성.** 노드 뷰가 `onCreate`보다 먼저 그려지기 때문입니다. 비용: 없음.
27. **동영상 iframe에 제공자 이름 title.** 파싱은 등록된 모든 제공자를 받고, 삽입은 `video.providers` 목록만 허용합니다. 비용: 없음.
28. **상황별 툴바의 표시 조건.** body 포털로 그리고, 데스크톱에서 포커스가 있을 때만 보입니다. 캡션 편집 중에도 이미지 상황으로 봅니다. 비용: 없음.
29. **슬래시 메뉴 규칙.** 드롭다운 하위 항목(제목 단계)도 검색 대상에 넣었습니다. 공백이 든 검색어가 결과 0개면 메뉴를 닫습니다(73에서 '공백이 들어가면 닫음'으로 바뀜). 비용: 없음.
30. **패널에 `onClose` 정리 훅.** 찾기 패널이 닫힐 때 강조 표시를 지우기 위해서입니다. 비용: 없음.
31. **UI 잠금은 루트 속성으로.** `data-locked-except` 속성으로 잠가서 소스 보기 중 다른 버튼을 비활성화합니다. 비용: 없음.
32. **전체화면 Esc 처리.** Esc는 루트에서 받고, 다른 처리기가 이미 쓴 키는 무시합니다(94에서 보완). 비용: 없음.
33. **계획 기대값 오류 수정.** 소스 보기의 기대값 `<p>bx</p>`가 틀렸습니다(script 내용은 버려짐). 비용: 없음.
34. **버블과 상황별 툴바 겹침 방지.** 링크 안에서 범위를 선택하면 버블 메뉴를 우선합니다. 비용: 없음.
35. **패널 공통 부모 `PortalPanel`.** 드롭다운과 바텀시트의 공통 동작을 한 곳에 모았습니다(DRY). 비용: 없음.
36. **기기 전환 시 재생성 범위.** 모드가 바뀌면 모드별 UI만 다시 만들고, 상태 표시줄 등 확장 컴포넌트는 유지합니다. 비용: 없음.
37. **모바일 막대와 커서 스크롤.** 모바일 막대 높이를 `scrollMargin`에 반영해서 커서가 막대에 가려지지 않게 했습니다. 시트 안 격자가 겹치던 문제도 E2E로 찾아 고쳤습니다. 비용: 없음.
38. **기기 인식형 E2E 도우미.** `control()`, `panel()` 도우미로 모든 E2E가 모바일에서도 돌게 했습니다. 비용: 없음.
39. **툴바 넘침 계산을 실제 측정으로.** 실제 `scrollWidth`로 판단하고, `[hidden]`이 `display` 규칙보다 우선하게 했습니다(리뷰의 Critical). 비용: 없음.
40. **앵커 없는 패널은 커서 옆에.** 툴바에 없는 항목의 패널은 커서 위치에 엽니다(리뷰 반영). 비용: 없음.

## 입출력, 래퍼, 빌드

41. **업로드 중 실행 취소 후 다시 실행의 알려진 한계.** 남는 미리보기는 `getHTML()`에 나오지 않지만 화면에는 보입니다. 비용: 드문 순서에서 유령 이미지가 보임.
42. **임시저장을 덮어쓰지 않는 시점.** 이전 임시본을 불러올지 버릴지 정하기 전에는 덮어쓰지 않습니다. `clearDraft`는 대기 중인 저장도 취소합니다(리뷰 반영). 비용: 없음.
43. **`STORAGE_UNAVAILABLE`의 전달 경로.** 생성 중에 발생해서 `on('error')`가 아니라 `console.error`로 갑니다. 비용: 앱이 이 오류를 이벤트로 받을 수 없음.
44. **소스 보기 편집은 입력 즉시 반영.** 입력하는 대로 문서에 반영합니다(리뷰 반영, 실행 취소는 55). 비용: 큰 문서에서 입력마다 다시 파싱함.
45. **붙여넣은 data: 이미지도 검사.** 형식·용량을 검사하고, 깨진 데이터는 알림과 함께 제거합니다(리뷰 반영). 비용: 없음.
46. **React와 Vue의 옵션 전달 방식.** React는 확장 옵션을 `options` prop으로 받습니다(`forwardRef` 내부 `Omit` 문제). Vue는 `getEditor()`를 노출합니다. 값이 `undefined`가 되면 비웁니다(리뷰 반영). 비용: React 래퍼 API 형태.
47. **언어팩 객체는 기본 언어 위에 병합.** 영어가 아니라 한국어 기본값 위에 병합합니다(리뷰 반영). 비용: 없음.
48. **아이콘 SVG의 xmlns 자동 추가.** 리뷰에서 Minor로 분류됐지만 문서 예제가 실제 브라우저에서 안 보여서 Important로 올려 수정했습니다. 비용: 없음.
49. **문법 강조는 작은 로더 모듈을 거침.** UMD가 highlight.js 전체 언어를 포함하던 문제(424KB)를 고쳐 175KB가 되었습니다. 비용: 없음.
50. **ESM 전용 패키지.** `module`/`types` 필드를 추가했고 CommonJS `require` 조건은 없습니다. 비용: CommonJS 전용 환경은 UMD 파일을 써야 함. 출시 전 점검에서 `require` 조건으로 그 UMD를 주도록 보완했습니다(114).
51. **공개 API 누락 보완.** 팩토리 3종과 `registerIcon`이 빠져 있어 추가하고 테스트로 고정했습니다. 비용: 없음.
52. **중복 코드 제거.** floating 위치 계산, 포커스 추적, 구분선, `capitalize`, U+FFFC 상수를 공용화하고 CSS 수치를 토큰으로 옮겼습니다(조직 규칙). 비용: 없음.
53. **도구 설정.** vitest pool을 명시했고 `@types/node`, `@types/react-dom`을 개발 의존성으로 추가했습니다. 비용: 없음.

## 출시 전 점검

출시 전에 8개 관점(코어 API, 내용 입출력, 보안, 데스크톱, 모바일, 통합·패키지, IME·접근성, 비동기·성능)으로 에디터를 점검했습니다. 점검자가 찾은 문제마다 다른 검증자가 재현하고 반박을 시도했고, 살아남은 73건(치명 6, 중요 42, 사소 25)을 9개 묶음(core, blocks, mobile, media, tables-view, paste, floating, a11y, integration)으로 나눠 고쳤습니다. 묶음마다 회귀 테스트가 있습니다(`tests/unit/audit-<묶음>.test.ts`, `tests/e2e/audit-<묶음>.spec.ts`). 병합한 뒤 5개 관점(묶음 사이의 상호작용, 코드 품질, 실제 브라우저, 패키지 소비자, 보안)으로 최종 리뷰를 했고, 같은 방식으로 검증된 38건도 모두 고쳤습니다(`tests/unit/final-review.test.ts`, `tests/e2e/final-review.spec.ts`). 아래는 고치면서 정한 동작입니다. "(최종)"은 최종 리뷰에서 정했거나 고친 것입니다.

### 코어와 폼

54. **destroy 뒤에는 아무 일도 하지 않음.** 공개 메서드는 모두 무시되고, `destroy` 리스너 안에서 다시 불러도 정리는 한 번만 합니다. 비용: 없음.
55. **불러오기와 편집을 나눔.** `setHTML`은 새 문서를 불러오는 것으로 보고 실행 취소 기록만 비웁니다(history 플러그인만 다시 만들어 찾기 상태와 바뀌지 않은 DOM은 유지, 결정 8 확장). HTML 소스 보기의 수정은 바뀐 범위만 바꾸는 일반 편집이라 실행 취소할 수 있고, 소스 보기를 열고 닫을 때 실행 취소 단계가 끊깁니다(최종). 비용: 소스 보기에서 입력할 때마다 실행 취소 기록이 쌓임.
56. **`uploadError` 인자는 `(file, error)`.** 다른 업로드 이벤트처럼 파일이 먼저 옵니다. 비용: 0.x 단계의 호환성 변경.
57. **언어 코드는 BCP 47 태그.** 대소문자를 가리지 않고 가장 구체적인 등록 팩을 찾으며(`ko-KR`→`ko`), 모르는 코드는 경고와 함께 `ko`로 보입니다. 비용: 없음.
58. **개발자 경고는 `warn()` 하나로.** `[laymaker]` 접두사를 붙여 일어날 때마다 남기고, 자주 도는 아이콘만 이름마다 한 번 남깁니다. 없는 툴바 ID 경고도 이 함수를 거칩니다(최종). 비용: 같은 실수를 반복하면 경고도 반복됨.
59. **textarea 모드는 `TextareaBinding`.** 생성 직후, change, submit(캡처 단계), formdata 때마다 에디터 HTML을 textarea에 넣고, 에디터를 원본으로 봅니다. 비용: 앱이 textarea 값을 직접 바꿔도 전송 때 덮어씀.
60. **formdata는 자기 항목을 자리로 찾음.** 같은 이름(`answers[]`)으로 전송되는 컨트롤 중 자기 위치의 항목을 바꾸고, 수가 맞지 않을 때만 옛 값으로 찾습니다(최종). CRLF는 LF로 맞춰 비교합니다. 비용: 없음.
61. **폼 reset은 생성 때의 내용으로.** reset 이벤트 안에서 바로 되돌리고, 취소된 reset은 무시합니다. 소스 보기 입력란과 체크리스트 상자는 `form` 속성으로 어느 폼에도 속하지 않게 해서 reset·검증·전송이 건드리지 않습니다(최종). 비용: 없음.
62. **required 표시 규칙.** 숨은 textarea의 invalid는 항상 취소하고, 사용자가 페이지를 조작한 뒤에만 빨간 테두리를 답니다. 포커스와 토스트(`toast.required`, `setCustomValidity` 문구 우선)는 전송 시도(제출 버튼, textarea가 아닌 칸의 Enter)에서 첫 무효 칸일 때만 합니다. 비용: 앱이 `checkValidity()`로 부르면 토스트가 없음.
63. **옵션 검사(`INVALID_OPTION`).** 함수·문자열 옵션은 `null`을 '지정 안 함'으로 받고, 확장 옵션은 기본값의 형태와 비교합니다(`NaN` 거부). 다른 문서(iframe)의 요소에는 붙일 수 없습니다. 비용: 섞인 형태의 옵션은 첫 원소와 비교됨.
64. **브라우저 API가 없는 환경.** `matchMedia`나 `ResizeObserver`가 없으면(앱의 jsdom 테스트) 미디어 쿼리는 맞지 않는 것으로, 크기 관찰은 없는 것으로 보고 데스크톱·라이트 테마로 동작합니다(최종). 비용: 없음.
65. **임시저장은 페이지를 떠날 때 바로.** `pagehide`와 화면이 숨겨질 때 기다리던 저장을 실행합니다(최종). 비용: 없음.

### 서식, 블록, 입출력

66. **코드 블록은 줄 단위.** 켜면 선택한 줄을 한 블록으로 합치고, 끄면 줄마다 문단이 됩니다. `hardBreak`는 `linebreakReplacement`라 블록 종류를 바꿀 때 개행과 `<br>`이 서로 바뀝니다. 비용: 없음.
67. **코드 블록에서 나가기.** 뒤에 아무것도 없는 블록 끝에서 ↓·→, 끝의 빈 줄 `exitBlankLines`개에서 Enter(Android는 입력된 개행으로)로 나갑니다. 표 칸 안에서는 표의 방향키 처리를 따릅니다. 비용: 없음.
68. **코드 언어의 줄인 이름.** ```` ```js ````·`language-py` 같은 이름(`DEFAULTS.codeBlock.aliases`)은 언어 메뉴에서만 정식 이름으로 읽고, 저장되는 클래스는 그대로 둡니다(최종). 비용: 같은 언어가 두 이름으로 저장될 수 있음.
69. **블록으로 시작하는 목록 항목.** `<li><h3>`처럼 시작하면 파싱 전에 빈 문단을 넣어 목록을 지킵니다. 판정은 앞쪽 자식 사슬만 따라가고 하위 트리를 파싱하지 않습니다(최종: 중첩된 90KB 입력이 12초 멈추던 문제). 비용: 그런 항목마다 빈 줄 하나.
70. **공백 저장 규칙.** 연속 공백과 줄 앞뒤 공백은 일반 공백과 `&nbsp;`를 번갈아 저장하고, 불러올 때는 반대로 일반 공백으로 되돌립니다. 저장할 때도 먼저 되돌린 뒤 저장해서 붙여넣은 `&nbsp;` 연속도 같은 모양이 되고, 붙여넣은 일반 텍스트의 탭은 코드 밖에서 `DEFAULTS.paste.tabWidth`(4)칸 공백이 됩니다(최종). 비용: 탭 정렬은 사라짐.
71. **블록을 넣은 뒤의 커서.** 구분선을 넣으면 뒤의 새 문단으로 갑니다. 동영상은 뒤에 이어지는 문단으로, 없으면 새 문단으로 갑니다(최종, `caretBelow`). 비용: 없음.
72. **목록 전환과 번호.** 목록 종류를 바꾸면 커서가 있는 단계의 목록 전체가 바뀌고, 체크리스트에서 나가면 체크 상태는 버립니다. 번호 목록의 `start`는 브라우저처럼 정수로 읽습니다(0과 음수 허용, 소수는 버림, 숫자가 없으면 1, 최종). 비용: 없음.
73. **슬래시 메뉴.** 검색어에 공백이 들어가면 닫고(결정 29 대체), 검색은 부분 문자열 일치입니다. 소스 보기 중에는 숨었다가 닫으면 다시 나옵니다(최종). 비용: '/heading 2'처럼 띄어 쓰면 닫힘.
74. **링크 스킴 보완은 스킴이 없을 때만.** 이미 스킴이 있는 주소(`mailto:a@b.co`)는 그대로 두어, 링크 패널에서 다시 적용해도 `mailto:`가 겹치지 않습니다(최종, 결정 14 보완). 비용: 없음.
75. **붙여넣기 색.** 무채색 글자색은 원본 페이지 색으로 보고 버리고(결정 16 확장), 남는 채우기 위의 더 밝은 회색 글자만 둡니다. 배경은 무채색이면서 아주 밝거나 어두운 것만 버리고, 유채색은 그대로 둡니다. 비용: 의도한 회색 글자와 아주 옅은 회색 음영도 사라짐.
76. **스타일은 CSSOM으로 읽음.** 단축 속성, `!important`, 여러 색 표기를 브라우저가 해석한 값으로 받고, CSS 2.1 색 이름 17개는 hex로 바꿉니다. 붙여넣은 `<code>`에는 안전한 `language-*` 클래스 하나만 남깁니다. 비용: 그 밖의 색 이름과 시스템 색은 버려짐.
77. **Word 목록 판정.** 숫자, 끝의 `.`·`)`, 원·괄호 문자 한 개는 번호 목록으로 보고, `lN`과 `lfoN`을 함께 보아 같은 목록인지 정합니다(미룬 항목 1 해결). 비용: 숫자가 든 사용자 정의 글머리표는 번호 목록이 됨.
78. **스타일→태그 변환을 블록과 셀까지.** 굵게·기울임은 자손의 자체 값이 이기고, 제목과 `th` 안에는 굵게를 더하지 않습니다. 블록 사이의 서식용 공백은 감싸지 않아 빈 문단이 생기지 않습니다(최종). 비용: 제목에 붙은 굵기 지정은 사라짐.
79. **`DEFAULTS.paste.defaultColors` → `pageColors`.** `colorStyles`, `namedColors`도 추가했습니다. 비용: 문서에 없던 값을 읽던 코드는 깨짐.

### 표

80. **칸 속성은 브라우저처럼 읽고 제한.** colspan·rowspan·`data-indent`는 앞쪽 숫자만 읽어 `DEFAULTS.tableLimits` 안으로 줄이고, 열 너비는 0~10000px입니다. 비용: 없음.
81. **채울 칸 한도.** 붙여넣기나 변경 한 번에 새로 채울 칸이 `maxFillerCells`(10,000)를 넘으면 큰 표부터 칸의 블록으로 풉니다. 비용: 아주 큰 짧은 행 표는 표가 아니게 됨.
82. **표 안의 커서.** 표를 넣으면 첫 칸으로 가고, 마지막 칸에서 Tab을 누르면 아래에 행을 더해 그 첫 칸으로 갑니다(최종). 비용: Tab으로 표 밖으로 나갈 수 없음(방향키로 나감).
83. **머리글 행 도구는 첫 행을.** 커서가 어느 칸에 있든 표의 첫 행을 켜고 끄며, 켜져 있으면 눌린 상태로 보입니다(최종). 비용: 중간 행을 머리글로 만드는 도구는 없음.
84. **열 너비는 `<colgroup>`으로도 저장.** 끌어서 바꾼 너비가 있을 때만 쓰고, 다시 읽을 때는 `data-colwidth`를 씁니다. 비용: 보기 페이지의 자동 표 배치에서는 너비가 다를 수 있음.
85. **모바일 칸 선택.** 글자 선택 핸들이 다른 칸까지 가면 칸 단위 선택으로 바꿉니다. 비용: 없음.
86. **색을 칠한 칸의 글자.** 칸 채우기도 형광펜과 같은 밝은 팔레트라 두 테마 모두 `--le-color-highlight-fg`를 쓰고, 글자색과 링크는 자기 색을 따릅니다(최종). 비용: 어두운 채우기에 글자색이 없으면 어두운 글자가 됨.

### 이미지, 동영상, 소스 보기

87. **data: 이미지 검사는 새로 들어온 것만.** 문서에 이미 있던 src(끌어 옮긴 이미지 포함)는 건드리지 않습니다(결정 45 범위 축소). 비용: 없음.
88. **소스 보기는 문서를 따라감.** 밖에서 문서가 바뀌면 커서를 같은 글자에 두고 다시 채우고, 업로드 중 노드는 적용 뒤 다시 넣습니다. 읽기 전용이면 입력란도 읽기 전용이고, 열 때 커서는 맨 앞입니다. 비용: 없음.
89. **캡션은 한 줄 글.** 캡션에서 들어온 이미지·여러 문단·줄바꿈 글은 그 이미지 뒤에 넣습니다. Enter·Shift+Enter·Ctrl+Enter는 캡션을 그대로 두고 이미지 뒤 새 문단으로 가며, Chrome Android가 캡션을 나눈 DOM 변경도 Enter로 읽습니다(최종). 비용: 캡션 안 줄바꿈은 없음.
90. **이미지 선택과 빈 캡션.** 그림을 클릭하면 노드 선택되고, 빈 캡션은 `le-caption-empty`로 숨기거나 안내를 보입니다. 비용: 없음.
91. **여러 파일은 고른 순서대로.** 비용: 없음.
92. **동영상 패널 문구는 `providers` 옵션으로.** 레이블과 오류 문구에 허용한 서비스 이름만 넣습니다(최종). 비용: 없음.

### 떠 있는 UI, 모바일, 접근성

93. **쌓임 순서는 토큰.** 상단 툴바 < 전체화면 에디터 < body 포털 < 토스트이고, `--le-z-overlay`는 10000입니다. 비용: 호스트 페이지 모달보다 위에 올 수 있음.
94. **Esc 순서.** 열린 패널, 슬래시 메뉴, 전체 화면 해제 순으로 한 번에 하나만 닫습니다. 전체 화면 해제는 키맵, 루트, 그리고 포커스가 페이지 본문에 떨어진 경우(읽기 전용 본문은 포커스를 받지 않음)에도 받습니다(최종, 결정 32 보완). 비용: 없음.
95. **패널 위치.** 연 버튼이 숨으면 선택 영역 아래로 옮기고, 넘침 메뉴에서 연 패널은 ⋯ 아래, 앵커 없는 패널은 선택 영역 전체 기준입니다(결정 40 보완). 비용: 없음.
96. **떠 있는 요소의 배치.** 버블·상황별 툴바·슬래시 메뉴는 autoUpdate로 대상을 따라가고, 상단 툴바와 모바일 키보드 위 툴바가 가린 가장자리를 피해 뒤집거나 높이를 줄입니다(모바일 막대는 최종). 비용: 화면보다 큰 대상은 여전히 겹칠 수 있음.
97. **토스트.** body 포털로 화면 아래 가운데, 키보드와 모바일 막대 위에 띄우고 같은 문구는 교체합니다. 오류 토스트 글자는 `--le-color-danger-fg` 토큰입니다(최종). 비용: 없음.
98. **포털의 테마.** 테마가 바뀌면 열린 패널, 토스트, 툴팁 등 모든 body 포털이 `ThemedPortal` 목록 하나로 곧바로 따라갑니다(툴팁은 최종). 비용: 없음.
99. **툴팁과 Alt+F10.** 툴팁은 body 포털로 호버·키보드 포커스에서만 보입니다. Alt+F10은 미뤄 둔 선택·UI 갱신을 먼저 반영한 뒤 상황별 도구 → 버블 → 메인 툴바 순으로 옮겨 갑니다. 비용: 없음.
100. **떠 있는 툴바의 포커스.** 포커스가 안에 있는 동안 유지하고, 숨을 때는 본문으로, 다시 그릴 때는 새 탭 정지점으로 옮깁니다. RovingFocus는 숨은 항목만 건너뜁니다. 비용: 없음.
101. **접근성 이름과 역할.** 패널은 연 항목의 레이블(`itemLabel`)로 이름 짓고 여는 버튼은 `aria-expanded`를 갖습니다. 목록 패널은 세로 `toolbar`, 편집 영역은 `textbox`입니다. 비용: 없음.
102. **대비 토큰.** `--le-color-active-fg`(4.5:1), `--le-color-control-border`(3:1), `--le-color-highlight-fg`, `--le-color-danger-fg`(최종)를 두어 두 테마 모두 WCAG AA를 지킵니다. 비용: 없음.
103. **마크를 받을 글자가 없으면 실패.** 코드 블록 등에서 글자색·배경색·링크 명령은 실패하고 버튼은 비활성입니다. 비용: 없음.
104. **읽기 전용에서 나가는 길.** UI를 잠근 항목과 켜져 있는 `viewToggle` 항목(전체 화면, 소스 보기)은 읽기 전용에서도 쓸 수 있고, 더보기 버튼도 안에 쓸 수 있는 항목이 있으면 활성입니다(전체 화면은 최종). 비용: 없음.
105. **모바일 키보드 위 툴바.** 편집 중에는 에디터 루트 안에 포커스가 있을 때 보이고, 읽기 전용에서는 켜진 화면 모드를 끄는 버튼만 포커스 없이 보입니다(최종). 비용: 없음.
106. **모바일 막대가 가리는 높이.** 막대 높이는 `scrollMargin`과 `scrollThreshold`에 함께 넣고(결정 37 보완), 막대와 화면 키보드가 가린 높이를 `--le-mobile-covered-height`로 알려 모바일 전체 화면이 그 위에서 끝나게 합니다(최종). 비용: 없음.
107. **바텀시트.** 배경은 click에서 닫고, 위쪽 44px 띠 전체가 끌기 영역이며, 열려 있는 동안 높이를 `--le-sheet-height`로 알려 찾기 결과를 그 위에 보입니다. 비용: 문서 끝 결과는 가려질 수 있음.
108. **패널 폼.** `panelForm()`은 `novalidate`이고, URL 입력은 스킴 없는 호스트에 `https://`를 붙여 명령에 넘기며, 거부되면 보이는 오류 문구를 띄웁니다(미룬 항목 13 해결). 비용: 없음.
109. **체크리스트 상자는 포커스를 가져가지 않음.** 클릭이나 탭으로 체크해도 글자 입력이 이어지고, 키보드(Tab, Space)로는 여전히 다룰 수 있습니다(최종). 비용: 없음.

### 래퍼와 패키지

110. **테마와 언어.** `setTheme` 값은 `editor.theme`으로 읽고 `setLocale` 뒤에도 유지합니다. 래퍼의 `locale` prop은 JSON 값으로 비교하고, `setLocale`은 같은 값이어도 다시 적용합니다. 비용: 없음.
111. **`registerIcon`은 HTML 파서로.** HTML 페이지에서 보이던 SVG 그대로 그리고, `<svg>`가 없으면 이름마다 한 번 경고합니다. 비용: 없음.
112. **Vue 래퍼.** `setup`에서 `{ host, getEditor }`를 돌려줘 타입에 들어가고, `@ready`로도 에디터를 주며, 에디터는 `markRaw` 해서 `ref()`에 넣어도 됩니다(최종). 비용: 부모 ref에 인스턴스 전체가 보임.
113. **React 래퍼의 마운트.** 브라우저에서는 `useLayoutEffect`, `window`가 없는 서버 렌더링에서는 `useEffect`로 에디터를 만듭니다(최종). 비용: 없음.
114. **CommonJS는 UMD 사본으로.** ESM이 기본이고, `require` 조건은 같은 UMD 번들의 `.cjs` 사본(`dist/editor.umd.cjs`)을 줍니다. `./editor.umd.js`도 내보냅니다(최종, 결정 50 보완). 비용: 패키지에 UMD 파일이 두 벌 들어가고, ESM과 CJS를 함께 불러오면 언어팩·아이콘 등록이 따로 놂.
115. **타입 해석.** 선언의 상대 import에는 `.js`를 붙이고, 스타일시트 내보내기는 빈 선언(`dist/css.d.ts`)을 가리키며, `typesVersions`로 `node10`에서도 `/react`·`/vue`를 찾습니다. 빌드는 node10, node16, nodenext, bundler와 스타일시트 import를 가상 설치본으로 검사합니다(최종). 비용: 없음.
116. **영어 상태 표시줄은 이름 먼저.** 한국어처럼 'Characters 1 · Words 1' 순서라 복수형이 필요 없습니다(최종). 비용: 없음.
117. **보기 페이지 정제 비용은 문서로.** `sanitizeHTML`은 에디터 스키마 전체를 쓰므로 보기 페이지에서 쓰면 에디터 번들 대부분이 들어간다고 usage.md에 적고, 서버 정제를 권합니다(최종). 비용: 가벼운 정제 진입점은 미룸(아래 15).
